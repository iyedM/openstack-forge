# Security

This section summarizes the security model and operational safeguards implemented in OpenStack Forge. **All 18 deployment steps remain marked `unverified` in the step catalog and none has ever been run on a real host.** For full details, see [`docs/engine/README.md`](../engine/README.md).

## Implemented safeguards

- **Root confinement and symlink rejection (`openstack_forge.execution.fsutil`):** every file read or write is resolved under an explicit `root` directory (`--root`), rejecting `..` traversal, symlinks that escape the root (`RootEscapeError`), and target files, parent directories, or `.orig` backups that are symlinks (`UnsafePathError`). File reads and editors reject NUL bytes (`\x00`). Atomic writes (`tempfile.mkstemp` + `os.fchmod` + `os.fsync` + `os.replace`) preserve original `uid`, `gid`, and `mode`.
- **Allowlisted command execution (`openstack_forge.execution.commands`):** external commands can only run through `CommandExecutor` and `DEFAULT_REGISTRY` (49 reviewed `CommandSpec`s with literal absolute executable paths, `shell=False`, `SANITIZED_ENV`, process-group timeouts, and strict parameter validation). No API accepts a shell command string, and `sudo`/`su` are forbidden.
- **Read-only enforcement (`read_only=True`):** `openstack-forge verify` constructs `CommandExecutor(..., read_only=True)`, which refuses any `CommandSpec` with `mutates=True` before invoking the backend or subprocess and never writes to `audit.log` or `state.json`.
- **Secrets, state, and audit storage (`openstack_forge.execution.secrets`, `state`, `audit`, `keystone`):**
  - `SecretStore` stores the 16 OpenStack passwords in `<root>/etc/openstack-forge/secrets.json` (directory mode `0700`, file mode `0600` created atomically via `tempfile.mkstemp`, owned by effective UID, no `.orig` backup, symlinks and group/world-accessible modes rejected).
  - `admin-openrc` is written to `<root>/etc/openstack-forge/admin-openrc` (not `/root/admin-openrc`) with directory mode `0700`, file mode `0600` created atomically via `tempfile.mkstemp`, and `create_backup=False`.
  - `StateStore` writes `<root>/var/lib/openstack-forge/state.json` (directory mode `0750`, file mode `0600` created atomically via `tempfile.mkstemp`, symlinks rejected on both load and write) and acquires an exclusive advisory `flock` on `<root>/var/lib/openstack-forge/apply.lock` (`os.open(..., O_CREAT | O_RDWR | O_NOFOLLOW, 0600)` + `os.fchmod(fd, 0600)`).
  - `AuditLog` appends JSONL records to `<root>/var/log/openstack-forge/audit.log` (directory mode `0750`, file mode `0600` via `os.open(..., O_WRONLY | O_CREAT | O_APPEND | O_NOFOLLOW, 0600)` + `os.fchmod(fd, 0600)`, symlinks rejected).
- **Redaction and zero secret leakage (`openstack_forge.execution.redaction`, `errors`, `preview`, `cli`):** every loaded or generated secret is registered for exact-value masking (`********`) alongside pattern-based redaction across diffs, `StepPreview` notes, `PlannedCommand`, `CommandResult` (including `__repr__`), `VerifyResult`, `StateStore`, `AuditLog`, CLI output, and exception messages (`UnexpectedExitError` redacts `stderr` at construction time). Only `openstack-forge secrets show NAME` outputs a secret value; `secrets init` and `secrets list` print secret names only.
- **Password delivery to child processes (`stdin`, `env_params`, and `argv` residual limitations):**
  - MariaDB SQL statements (`mariadb.execute-sql`) deliver SQL and passwords over `stdin` (`stdin_param="sql"`).
  - `keystone.bootstrap` delivers the admin password via `OS_BOOTSTRAP_PASSWORD` (`env_params={"password": "OS_BOOTSTRAP_PASSWORD"}`).
  - All 11 `/usr/bin/openstack` commands (`openstack.*`) authenticate as `admin` via `OS_PASSWORD` (`env_params={"admin_password": "OS_PASSWORD"}`); `--os-password` is never passed in `argv`.
  - **Documented residual `argv` limitations imposed by upstream CLIs:** 4 `CommandSpec`s out of 49 must pass the target user's password in `argv` because the upstream CLI provides no non-interactive `stdin` or environment variable option for the target user password:
    1. `rabbitmqctl.add-user` (`/usr/sbin/rabbitmqctl add_user openstack {password}`)
    2. `rabbitmqctl.change-password` (`/usr/sbin/rabbitmqctl change_password openstack {password}`)
    3. `openstack.user-create` (`/usr/bin/openstack ... user create --domain default --password {user_password} {username}`) — note: `admin_password` is in `OS_PASSWORD`, only the new service user's `user_password` is in `--password`.
    4. `openstack.user-set-password` (`/usr/bin/openstack ... user set --domain default --password {user_password} {username}`) — note: `admin_password` is in `OS_PASSWORD`, only `user_password` is in `--password`.
    All 4 declare `sensitive_params`, are masked as `********` by `redact_argv` in previews, `CommandResult.argv`, `audit.log`, and exceptions, and are documented in [`docs/engine/README.md`](../engine/README.md). To prevent unprivileged local users from reading `/proc/<pid>/cmdline` during those brief invocations on shared hosts, mount `/proc` with `hidepid=2` (or `hidepid=invisible`).
- **Host safety guards:** `neutron-controller` and `neutron-compute` refuse `apply` when the provider interface is the management interface or carries `management_ip` (unless `allow_shared_provider_interface: true` is set); `cinder-storage` refuses `apply` when the root filesystem `/` is on LVM and would be hidden by `/etc/lvm/lvm.conf` (unless `allow_lvm_root_filter_override: true` is set); and `apply --yes` acquires an exclusive advisory lock at `<root>/var/lib/openstack-forge/apply.lock`.
